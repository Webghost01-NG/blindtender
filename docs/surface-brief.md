# BlindTender MVP surface brief

## Direction contract

### World

BlindTender uses a restrained black-and-white security instrument language, informed by the clarity and motion discipline of PamoSafe without copying its brand, content, or page composition. White space, large type, pill-shaped controls, and strict contrast make the evidence workflow feel calm and trustworthy.

### First viewport

A floating capsule navigation identifies the tender and the active role. A five-stage evidence path establishes Rules, Submit, Closure, Award, and Settlement. Exactly one stage occupies the main workspace. At Closure, the user sees only three acknowledged commitments, a clear explanation, one primary close-and-sign action, one secondary rules action, and a closed evidence-details disclosure.

### Visitor path

1. Choose a role.
2. Complete or inspect the active evidence stage.
3. Advance to the next stage after a successful operation.
4. Open evidence details only when verification or a dispute requires them.
5. Use dedicated failure scenarios to inspect tampering and omission evidence.

### Signature interaction

The active marker moves along a thin security-thread path when the workflow advances. Content enters once with an 8px rise and fade. Controls compress to 0.97 on press. No element animates continuously, and reduced-motion preferences disable movement.

### Cross-surface reach

The same capsule navigation, large typography, black/white palette, stage thread, pill controls, spacious list rows, and progressive disclosure govern supplier, operator, auditor, challenge, and settlement states.

### Risk

Extreme visual restraint could hide cryptographic depth. The evidence-details disclosure and dedicated auditor view preserve technical inspectability without forcing it into the primary workflow.
